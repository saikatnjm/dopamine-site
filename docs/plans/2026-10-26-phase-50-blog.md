# Phase 50: Blog (ব্লগ)

**Status:** planned · **Written:** 2026-10-26 · **Estimated size:** about 2 days for the system, plus
about half a day per article (research, draft, owner review)

**Index:** [ideas backlog](2026-10-25-ideas-backlog.md) · **Related:** [Phase 49 SEO](2026-10-26-phase-49-seo.md)
listed "a blog" as out of scope; this phase adds it on top of Phase 49's SEO tools

## 1. Goal

A **Blog / ব্লগ** section in the main menu with **researched, genuinely useful articles**. People
search for things like "লাটিম খেলার নিয়ম", "64 districts of Bangladesh list" or "marble game rules".
Each article answers that question well and then sends the reader into a matching Hottogol game.

**Why:** game pages can only rank for "play X online". Articles can rank for the much larger
**informational** searches around the same topics, and every article is a doorway to a game.

### What the blog is not (so pages don't compete with each other)

| Page type | Search intent it owns | Example |
|---|---|---|
| Game page + Phase 49 step C "how to play" | "play X online", controls, scoring in **our** game | `/games/latim-fight` |
| Guide pages (`data/guides.ts`) | "games to play when bored", "funny websites": **lists of our activities** | `/one-minute-games` |
| **Blog article** | **Facts, culture, history, places, language**, with no "play online" angle | "How লাটিম is played in Bangladesh: বেল্লা পার and ঘর কোপ" |

**Rule:** an article never targets "play … online" or "games when bored", and a guide never targets
a facts or history query. If a topic fits both, it belongs to the game page or guide that already
exists.

## 3. Content model (TypeScript data, no new dependencies)

The repo keeps content as validated TypeScript (guides, dialects, clues). Don't add MDX or a CMS.

`data/blog/<slug>.ts`, one file per article, collected in `data/blog/index.ts`:

```ts
type BlogPost = {
  slug: string;              // /^[a-z0-9-]{1,60}$/, permanent (URLs, links). Never rename or reuse
  status: "draft" | "needs_review" | "published"; // only "published" renders, is listed, or is in the sitemap
  published: string;         // YYYY-MM-DD, a real date
  updated?: string;          // YYYY-MM-DD, only when the content really changed
  topic: "traditional-games" | "places" | "language" | "dhaka-life"; // index filter chips
  title: { en: string; bn: string };          // H1
  seo: { en: { title: string; description: string }; bn: { title: string; description: string } };
  lead: { en: string; bn: string };           // 1–2 sentence intro, also the card text
  cover: { emoji: string; accent: Accent };   // card + OG image (no stock photos)
  body: readonly Block[];                     // see below
  play: readonly string[];                    // 1–3 activity keys from listActivities(), shown as "Play it now" cards
  sources: readonly { title: string; url: string }[]; // required for any factual claim
  faq?: readonly { q: Text; a: Text }[];      // optional, visible on the page
};

type Block =
  | { kind: "h2"; text: Text }
  | { kind: "p"; text: Text }
  | { kind: "list"; ordered?: boolean; items: readonly Text[] }
  | { kind: "table"; head: readonly Text[]; rows: readonly (readonly Text[])[] }
  | { kind: "callout"; tone: "tip" | "note"; text: Text }
  | { kind: "activity"; key: string }   // inline ActivityCard
  | { kind: "map"; districts?: readonly string[] }; // reuse components/games/district-map.tsx (server-rendered, CC BY credit visible)
```

`Text` is the existing bilingual type, rendered with `t()`. Paragraph text supports `[link text](/path)`
**internal links only**, parsed by a tiny renderer. Nothing else in the text is parsed, so there's no
HTML injection.

### Validation (`lib/blog.ts`, runs at import, so bad data fails the build)

- Unique slugs; `published`/`updated` are real dates, not in the future, with `updated` ≥ `published`.
- Every `play` and `activity` key exists in `listActivities()`, and every map district id exists.
- Every internal link resolves to a real route.
- `sources` is non-empty when `topic` is `traditional-games`, `places` or `language`.
- **Minimum substance:** ≥ 600 English words in body paragraphs and lists, and ≥ 3 `h2` sections.
- **No duplicate paragraphs** across articles, guides and Phase 49 step C how-to text. Reuse the
  duplicate check in `lib/guides.ts`, or extract it to a shared helper.
- SEO lengths use the Phase 49 limits (`tests/seo.test.ts`: title ≤ 70 with the suffix, description
  70–160, unique across indexable pages). Add blog pages to that test.
- An EN/BN pair is required for every `Text`. The owner polishes the BN.

### Editorial process (same spirit as the dialect and clue rules)

1. A research chat drafts an article from sources it actually opened, with `status: "needs_review"`.
   **Never invent facts, statistics, quotes or "studies".**
2. The owner reads it, fixes the BN, and sets `status: "published"` plus the `published` date.
   **Code and AI never set `published`.**
3. Pace: **quality over volume**, at most 1–2 articles a week. Mass-producing near-identical AI
   articles can get a whole site demoted (Google's "scaled content abuse" policy), so every article
   needs a real angle and real sources.
4. Tone: AGENTS.md rules apply. Jokes about situations, never people, groups, districts, religion or
   politics.

## 4. Routes and pages

| Route | What it shows |
|---|---|
| `/blog` | H1 "📝 Hottogol Blog" / "📝 হট্টগোল ব্লগ" and a one-line intro, then topic chips (All / Traditional games / Places / Language / Dhaka life), then article cards newest first (emoji cover, title, lead, date, reading time). The chips filter client-side as progressive enhancement; without JS every card shows. Pagination only after 20 articles |
| `/blog/[slug]` | Breadcrumbs (Hottogol › Blog › Title), H1, date ("Updated …" only if `updated`), reading time, lead, body blocks, "▶ Play it now" cards (`play`), FAQ (if any), "📚 Sources", "More from the blog" (2–3 other articles: same topic first, then newest), `<RelatedLinks>` |
| `/blog/feed.xml` | RSS 2.0 of published articles (English titles and leads). A route handler with no dependency. Linked with `<link rel="alternate" type="application/rss+xml">` on `/blog` |
| `/bn/blog`, `/bn/blog/[slug]` | Via Phase 49 step B: Bangla text, BN SEO strings, hreflang pairs |

- **Rendering:** server components only, no client JS except the optional filter chips.
- **Unknown or unpublished slugs:** `notFound()`. Use `generateStaticParams` for published slugs.
- **Reading time:** English word count ÷ 200, rounded up, minimum 1. For Bangla, show the same
  minutes in Bangla digits.
- **Byline:** none (standing instruction 9). At most a "Hottogol" label. No author pages.

## 5. SEO (use the Phase 49 tools; never hand-write metadata)

- **Metadata:** add `blogIndexMetadata()` and `blogPostMetadata(post)` to `lib/seo-pages.ts`, both
  built on `pageMetadata()`. Add `/blog` to `PAGE_SEO` in `data/seo.ts`.
- **Share image:** `blogOgImage(slug)` in `lib/og-cards.tsx` (emoji, English title, accent; same style
  as `gameOgImage`), used by `app/blog/[slug]/opengraph-image.tsx`. The index uses `pageOgImage("blog")`.
- **JSON-LD** via `<JsonLd>`:
  - `/blog`: `Blog` with `blogPost` items, or an `ItemList`, plus breadcrumbs.
  - Articles: `BlogPosting` with `headline`, `description`, `datePublished`, `dateModified` (= `updated`
    or `published`), `image`, `inLanguage`, `mainEntityOfPage`, and `publisher` (and `author`) =
    the `#organization` node. **Never a person** (standing instruction 9).
  - Plus `FAQPage` only when the FAQ is visible, and breadcrumbs.
- **Sitemap:** `/blog` and every published article, with `lastModified` = `updated ?? published`
  (real dates only), plus the `/bn` alternates from step B.
- **Internal links, both directions:**
  - Each article links to its 1–3 games.
  - Each linked game page shows a small "📖 Read: <article title>" link under the game. Add an
    optional `article` lookup by activity key in `lib/blog.ts`, rendered by the game page or by
    `RelatedLinks`.
  - `/bored` and the guides may link to 1–2 fitting articles.
  - Re-check that every activity still has ≥ 3 inbound links.

## 7. Analytics (no new events needed)

- `page_view` and `activity_view` are automatic.
- Clicks on "Play it now" and inline activity cards: `recommendation_click`
  {source: "blog", from: `blog:<slug>`, activity, position}. `source` and `from` are already in the
  GA allowlist (check `lib/analytics-taxonomy.ts`).
- The "📖 Read" link on game pages: `recommendation_click` {source: "game_article"}.
- **Success metric for the owner (GA4):** blog sessions that lead to `activity_start`, per article.
  An article that ranks but sends nobody to a game should get a better "Play it now" section, not
  more articles.

## 10. Tests

- **`tests/blog.test.ts`:**
  - validation catches: a duplicate slug, an unknown activity or district, a broken internal link,
    missing sources, a future date, `updated` < `published`, a missing BN, too few words or sections,
    and a duplicate paragraph across a post and a guide;
  - unpublished posts are excluded from `publishedPosts()`, the sitemap and the feed;
  - reading time;
  - related-article picking (same topic first, never itself).
  - Use **fake fixture posts**, never real claims.
- **`tests/seo.test.ts`:** blog index and every published article pass the length, uniqueness and
  canonical rules.
- **RSS:** valid XML (parse it), escaped titles, absolute URLs.
